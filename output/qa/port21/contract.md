# PORT-21 navigation contract review history

The initial draft below is retained for review provenance. Revisions override earlier
details; revision 2 was approved independently before implementation. See `review.md`
for subsequent fixes and `docs/click-navigation.md` for the current maintenance guide.

Scope: generic click/tap movement and selected-object approach, not collision or artwork redesign.

- Keep an internal grid planner, no new package. A* for exact points, Dijkstra for predicate/multi-goal approach. Grid spacing 4 world pixels; keep exact start/end connectors. Static geometry caches are shared across requests. Maximum 100,000 grid nodes/expansions. Search progresses in bounded frame slices (4ms, at most 128 expansions per slice), at most 2 seconds overall; failure is explicit. No promise/timer retry loop.
- Geometry coordinates are world-pixel centers of the actual foot body. Obtain width/height and body-to-sprite offset from Player, never derive from visual asset dimensions. Build forbidden geometry from existing getAllCollisionRects plus the world rectangle minus the union of rooms/corridors. Expand forbidden rectangles by half the player body plus 0.05px clearance. Exact swept segment/rectangle checks prevent corner cutting and unsafe endpoint connectors. Reject non-finite/out-of-world requests. No route smoothing unless segments are explicitly validated.
- Use a fixed world grid with start connections to nearby valid nodes, including fractional starts; directly connect visible exact endpoints. Verify current house narrow corridors and furniture clearances in tests; if spacing misses accepted passages, refine before approval rather than changing collisions.
- Follower owns only intent and velocity, not physics. Player accepts optional desired velocity while keeping normal manual movement/facing/cadence. Steer at <=144px/s, stop within 0.15px, bound final speed to remaining distance per physics step. Stop/replan is NOT automatic; stalled progress for 0.75s fails once. 30 seconds maximum route duration. Active request identity disappears on cancellation or replacement, so stale arrivals cannot dispatch.
- Interaction goals convert hypothetical foot centers into the exact existing player position and interaction bounds in logical tiles. Only the selected stable object ID can open, after actual post-physics range revalidation; already in range stops and opens once. Shared content IDs are not destinations.
- Pointer events bind to canvas only; primary left mouse/completed single-finger tap <=8 CSS px displacement and <=600ms. Multi-touch invalidates all current gestures, pointercancel/blur/hidden clears gesture. Release must hit canvas; no DOM pointer propagation to canvas. Native PointerEvents only avoids compatibility-click duplication. Camera conversion uses current canvas logical size and getWorldPoint; no camera auto-pan.
- UI feedback uses existing app bridge with a small aria-live non-modal status. Invalid floor targets cancel old navigation and remain stopped; do not substitute nearby points. Manual movement, explicit interaction, quick travel, modal disable, blur/hidden, scene shutdown cancel. New click replaces and stops previous route before planning. Keyboard and mobile controls remain.
- Deterministic hits: visible padded label before logical radius, distance to candidate region center then stable ID. Visibility diagnostics never gate radius hits. Selected intent does not assert proximity. Existing manual nearest-target semantics remain unchanged.
- Review gates: independent architect/game developer approve this contract; independent senior engineer/game developer review implementation with fix/re-review iterations. No push or Done before owner visual acceptance. Evidence distinguishes emulation from physical devices.

## Review revision 1 — overrides draft details above

- Use grid coordinate axes with 4px regular samples PLUS every expanded obstacle boundary and the exact start/end coordinates. This supports fractional origins, touching starts, narrow channels and exact endpoint graph nodes without nearest-node connectors. Use zero clearance padding, matching physics: contact with a boundary is legal, interior overlap is not. Segment slab checks treat rectangle interiors as forbidden. All start/end points must be clear; no snapping or escaping an actually embedded start. Graph optimality is over sampled valid vertices/edges, not continuous-space optimality. Object goals require the exact predicate; arrival must satisfy that predicate, otherwise fail explicitly rather than remote-open.
- Caps: 500,000 potential vertices, 100,000 expansions, 800,000 heap entries, geometry input <=2,000 rectangles. Check time after each expansion (up to eight segment checks) and yield every expansion to the driver, which advances for at most 4ms and 128 expansions per frame. Search deadline 2 seconds wall clock. Geometry subtraction has a 10,000-piece cap; startup geometry is timed and tested against 50ms budget on development hardware. Failure types invalid/unreachable/budget-exceeded/cancelled/stalled are distinct internally, with brief readable feedback.
- Physics WORLD_STEP observes actual body progress and prepares velocity for the NEXT physics step, including catch-up steps. Scene update may apply the most recent prepared velocity but never replace it with manual zero during active navigation. At final arrival stop velocity within WORLD_STEP, then queue the pinned-object dispatch for POST_UPDATE after body-to-sprite sync. Steer using fixed physics dt (1/world.fps); when fixed stepping is disabled use a conservative actual step duration and test separately or explicitly reject that unsupported setting (project uses fixed stepping).
- Foot-to-interaction conversion: body center (cx,cy), measured sprite-to-foot offset (ox,oy), body size (w,h), tile size T produce anchor position ((cx-ox)/T-0.5,(cy-oy)/T-0.5), and interaction bounds ((cx-w/2)/T-0.5,(cy-h/2)/T-0.5,w/T,h/T). Clear dispatch eligibility before invoking UI callbacks. Final object goal is reached to <=0.01px; if current predicate still fails, emit failure, not retry indefinitely.
- Cancellation hooks fire on any manual intent (including opposing keys), explicit interaction even with no target, resetMovement (including quick travel), gameplay disabling, blur/hidden and shutdown. They synchronously clear search/route/arrival and stop automatic velocity. Progress requires reducing current waypoint distance by >=0.1px; reset the timer on waypoint advance. Overall route timeout 30s prevents repeated tiny progress indefinitely.
- Pointer adapter tracks maximum displacement and all document pointer IDs; any second pointer invalidates the pending gesture. No pointer capture required: document pointerup/cancel clears state, release is accepted only when elementFromPoint is canvas. Pointerleave does not accept a command. Blur/visibility/resize/modal/manual cancellation clears gesture. During an active manual hold, clicks are ignored. DOM overlay events never issue navigation.

## Review revision 2

- Steering validates the full segment from the actual current foot center on every physics step; if collision displacement makes it unsafe, fail once. A newly found route prepares its first velocity immediately before the next simulation, then WORLD_STEP owns progress/next velocity. Waypoint tolerance is 0.01px, not 0.15px.
- Object goal queries provide two nearest-point projections for each expanded graph vertex (one onto radius/rounded-rectangle region in sprite-anchor space; one onto padded label overlap region in foot-center space). Validate each connector's exact swept clearance and resulting interaction predicate. Treat validated connectors as terminal weighted edges; Dijkstra may return only when the best terminal cost is <= the next frontier cost. Include region center/boundary coordinates in axes. This avoids relying exclusively on vertices accidentally lying inside a thin region. Optimality is among this explicitly finite graph and its projected connectors; no continuous-space optimality claim.
- Numeric rules: exact numeric axis deduplication using Set (never epsilon-merge passages); reject non-finite values. Segment/rectangle slab intersection excludes boundaries, includes any nonempty open interior interval, including simultaneous-corner cases only when the path enters an interior. Parallel axes test strict interior; zero-length segment uses strict point containment. Floating boundary rounding is fail-closed, never enlarge an obstacle gap with tolerance. Only arrival/progress comparisons use tolerance, never clearance.
- The 4ms slice is a cooperative target (may exceed by one expansion); time setup/axis sort/allocation separately with a 50ms setup budget and fail budget-exceeded if exceeded. Cap axes/product before per-node allocations. No enormous array allocated before bounds validation. Measure fixture/browser budgets before acceptance.
- Quick travel cancels at click time, not artwork completion. While loading, navigation input is suspended via the gameplay-enabled boundary, then re-enabled in finally only if the same scene is live and no modal is open. Closing a modal or a loading failure never resumes a cancelled route. Overall route timeout includes planning.
- Evaluate vertices/edges and goal connectors lazily as expanded; no full-product walkability or goal enumeration. Use actual Euclidean edge lengths on irregular axes; exact-point heuristic is Euclidean, multi-goal heuristic is zero. Reconstruction is bounded by visited count and yields per parent link under the same cancellation/deadline. Axis preparation is bounded by input/axis limits and its 50ms measured setup budget; use sparse maps for query scores/parents.
